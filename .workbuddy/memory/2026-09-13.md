## V3.54（SW v83）修复进货明细宽表格撑破整页 + 手机端旧缓存残留 — 推送部署

**用户反馈（手机端）**：① 选货区仍显示 V3.53 已删除的「＋再加」；② 新建进货单**整页宽度被撑破**、可横向滚动，进货明细模块宽度影响了整个页面。

**根因（两个独立问题）**：
1. **整页撑破 = 经典 CSS Grid 溢出**。`.purchase-form-grid` 是 grid，子项默认 `min-width: auto`，被内部超宽表格（`table.tbl td { white-space: nowrap }` 的「进货明细」5 列表）撑到 `min-content` 宽度 → 整条 grid 轨道与整页一起被撑宽（手机端尤其明显）。
2. **「＋再加」残留 = 缓存新鲜度**。GitHub Pages 静态资源带 `Cache-Control: max-age=600`，network-first 的 `fetch(req)` 在 10 分钟内直接命中浏览器 HTTP 缓存、返回旧 JS/CSS（SW 是 network-first 也救不了）。

**修复**：
- `css/base.css`：`.purchase-form-grid { grid-template-columns: minmax(0,1fr) minmax(0,1fr) }`；`.purchase-form-grid > .card { min-width: 0 }`；`.purchase-form-grid > .card .table-wrap { min-width: 0 }`；`.card { min-width: 0 }`（防御）；`.pick-name { overflow-wrap: anywhere }`（超长型号换行）
- `css/mobile.css`：`.purchase-form-grid { grid-template-columns: minmax(0, 1fr) }`；`.app-main { overflow-x: clip }`（兜底；**clip 不产生滚动容器**，不影响 window 纵向滚动与 V3.48/V3.49 滚动保持逻辑）
- `sw.js`：两处 `fetch(req)` → `fetch(req, { cache: 'no-cache' })`（强制与服务端重新校验，未变更返回 304，几乎不增流量）
- `js/ui/page-mine.js`：关于卡片新增 **「🔄 检查更新」按钮**（`data-act="check-update"`：清空 SW 缓存 → `registration.update()` → `location.reload()`），作为旧缓存兜底自救入口

**真机尺寸浏览器实测（Playwright + Chromium，390px 视口，`isMobile:true`）**：
| 变体 | 布局视口 | 卡片宽度 | 页面溢出 |
| --- | --- | --- | --- |
| 修复前（`1fr` + `min-width:auto`） | **595px**（被撑破） | 583px | 横向溢出 |
| 仅 grid 修复（去掉 clip 兜底） | 390px | 366px | 0 |
| 当前 V3.54 | 390px | 366px | 0 |
→ 证明 grid `minmax(0,1fr)` + `min-width:0` 本身即可封住溢出，`overflow-x: clip` 只是保险。加入按钮 30×45px 竖排不变。

**测试**：新增 3 项（grid `minmax(0,1fr)` + 子卡片 `min-width:0` + `.app-main overflow-x: clip`；`.pick-name overflow-wrap: anywhere`；sw.js 两处 `fetch(req,{cache:'no-cache'})`），更新 3 项（ui-purchase 两处 grid 断言、sw-cache network-first 断言、ui-mine 版本号 + 检查更新按钮）。全量 **694/694** 通过。

**发布**：main `fda180d`；tag **`v3.53-baseline`** → `138fe7f`（回滚基线）；gh-pages 待推送（SW v83）。

> **重要经验（务必记住）**：
> 1. 本项目的横向溢出 bug 首选排查 **grid/flex 子项 `min-width:auto`**——宽表格（`td { white-space: nowrap }`）会经 grid `1fr` 轨道把整页撑破。修复范式：`minmax(0,1fr)` + 子项 `min-width:0`，让 `.table-wrap` 内部滚动。
> 2. **部署后手机端仍显示旧界面，几乎一定是缓存**（GitHub Pages `max-age=600` + SW 缓存），不是代码没生效。先 `git show <branch>:<file> | grep` 确认线上文件已更新，再查缓存。SW 的 network-first 必须配 `fetch(req,{cache:'no-cache'})` 才能穿透 HTTP 缓存。用户端可点「我的 → 关于 → 🔄 检查更新」自救。
> 3. 布局类改动建议用 **Playwright + Chromium 在 390px 视口实测**（`playwright-core` 在 `/Users/ybf/.workbuddy/binaries/node/workspace/node_modules`，chromium 在 `~/Library/Caches/ms-playwright`，需 `NODE_PATH` 指向 workspace）验证 `document.documentElement.scrollWidth` vs `innerWidth`，比只看代码可靠。
