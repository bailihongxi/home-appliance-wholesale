## V3.51（SW v80）手机端选货区右侧排版优化 — 推送部署

**需求**：V3.50 选货区在手机端单行已能容纳，但用户希望右侧「加入」按钮更紧凑、更有视觉识别：
1. 将库存数字放置到 加入按钮前面（即左侧，靠近品牌+型号卡片信息那侧）
2. 加入按钮两个汉字「加入」从横排排版更改为竖排排版
3. 加入按钮宽度收缩 30%（≈30px）、高度增大 50%（≈45px）
4. 加入按钮排布位置不变（仍在卡片右侧）

**实现（仅 `css/mobile.css` `@media (max-width:599px)`，电脑端 ≥600px 沿用 V3.50 不变）**：
- `.pick-side`：`flex-direction: column` → `row`，`align-items: center; gap: 8px`（库存数字与按钮横向并排）
- `.pick-side .pick-stock { order: 0 }`：库存前置
- `.pick-side .btn { order: 1; width: 30px; height: 45px; padding: 0; line-height: 1; font-size: 13px; letter-spacing: 0; writing-mode: vertical-rl; text-orientation: upright }`：
  - `writing-mode: vertical-rl` 让「加入」两个汉字沿竖直方向排版（加 上、入 下）
  - `text-orientation: upright` 保证汉字保持正立（不旋转 90°）
  - 按钮宽度 30px（基础 `.btn-sm` 约 44px，-30%）、高度 45px（min-height 30px + 50%）

## V3.52（SW v81）选货区双布局切换 — 推送部署

**需求澄清**：用户指出 V3.50 + V3.51 的两行卡片式排版只应应用于手机端，电脑端（≥600px）应保持 V3.49 时期的多列横向表格，不应被卡片式覆盖。即"把 V3.49 的样式应用到电脑端，把 V3.51 的样式应用到手机端"。

**实现**：
- JS：销售开单 / 新建进货单按商品加行 / 退换货换货 三处选货区同时渲染**两份**标记：
  - `<div class="pick-desktop">` 包 V3.49 风格 `<table class="tbl tbl-striped">` 横向表格（销售开单：商品/批发/零售/库存/加入；进货：商品/档案成本/库存/加入；换货：商品/批发/零售/库存/加入）
  - `<div class="pick-mobile">` 包 V3.51 风格 `.pick-list` 两行卡片
- CSS：
  - `base.css` 默认（≥600px）：`.pick-desktop { display: block }`、`.pick-mobile { display: none }`
  - `mobile.css` `@media (max-width: 599px)` 反转：`.pick-desktop { display: none !important }`、`.pick-mobile { display: block !important }`
- **CSS-only 响应式切换**：窗口宽度跨越 600px 时 CSS 自动切换，无需 JS 重渲染（不会重置滚动位置、不会重新触发 .table-wrap scrollLeft 保持逻辑）。

## V3.53（SW v82）取消「加入」按钮变换为「＋再加」样式 — 推送部署

**需求**：手机端与电脑端都取消「点击加入后按钮变换为『＋再加』」的样式。该变换无意义——数量应在「进货明细列表」或「当前订单列表」中修改；且更长文案会撑宽按钮、破坏页面宽度（尤其手机端两行卡片右侧固定宽度布局）。

**实现**（仅改 `js/ui/page-purchase.js`，销售开单/退换货换货选货区本无此逻辑）：
- 桌面端 `pick-desktop` 表格：移除 `var hasD = state.form.items.some(...)` 判断分支，按钮固定显示 `加入`
- 手机端 `pick-mobile` 卡片：移除 `var has = state.form.items.some(...)` 判断分支，按钮固定显示 `加入`
- 点击「加入」的行为不变（该商品一行，数量 +1），仅按钮文案不再变化、宽度稳定

**测试**：`tests/pick-list.test.js` 新增 1 项——先把商品加入 `state.form.items` 模拟「已加入」状态，断言渲染结果不含「＋再加」/「+再加」，按钮数量保持 4（seed 的 2 款商品 × 双布局）。
