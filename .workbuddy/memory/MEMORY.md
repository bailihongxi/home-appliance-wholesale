# 项目长期笔记 · 家电批发进销存

## 数据模型：账号 ≠ 一本账

- **共用本店数据**：员工的 `ownerId='admin'`，与老板共用同一个 IndexedDB 库 `applianceErp_admin`。
  权限只决定「能看什么 / 能做什么」，**不隔离数据**。
- **数据归属判定**：`accounts.dataOwnerId(a) = ownerId || id`；
  `sync.isDataOwner(a)` 为真的才是「可上传者」（老板 / 管理总控 / 独立数据空间账号）。

## 员工账号：三条硬边界（反复被问，务必先确认再答）

1. **不能上传云端** —— `page-mine.js` 的 `sync-up` 动作对非数据归属者**无条件禁止**
   （不看 `data_manage` 权限），提示「本账号为只读拉取，不能上传到云端」。
   **根因（设计如此，勿改）**：员工拉取快照时经过 `filterSnapshotForAccount` **按 createdBy 过滤**，
   本机只有「自己名下的单」+ 全店商品/库存；若允许上传会用这份残缺数据**冲掉全店快照**。
   → **推论：员工在自己手机上开的单，只留在本设备，不会自动汇入老板的账本。**
   若需共用同一本账，员工须与老板**在同一台设备**上登录操作。
2. **没有「同步设置」面板、没有 Token 输入口** —— V3.73 起员工的云同步卡片只有一个
   「从云端恢复」按钮（`renderSyncCard` 按 `canUpload` 分支）。
3. **不需要 Token** —— V3.79 起「从云端恢复」走 GitHub Pages 公开静态快照，
   只依赖「取数口令」+ 可推断的地址；owner/repo/branch/path/Token 全缺也能拉。

## 取数口令（凭证）流转 —— 全自动，别让人手工配

- 发放：管理总控在「账户权限管理」**保存员工密码**时 `wrapPhrase(员工密码, 同步口令)`
  → 写入 `account.syncPhraseEnc`
- 认领：员工登录时 `page.claimCredential` 用其登录密码 `unwrapPhrase` 解出口令，
  按 `dataOwnerId` 写入本机同步配置
- → **员工只要能登录就自动有取数口令**，无需人工给任何字符串
- 改密码 / 换设备后：需老板重新保存一次员工密码，员工重新登录一次

## 员工权限清单（`accounts.js`，16 项 / 4 组，全手动勾选，无角色模板）

- 零售：零售开单（含扫描）、零售收款/抹零、零售退货/作废、零售改价/折扣
- 批发：批发开单（客户挂账）、批发收款/核销、批发退货/作废
- 档案·库存：商品档案（只读，隐藏成本/利润列）、库存查询（只读）、进货入库/供应商、
  商品建档/改价/合并/删除、库存盘点/调整
- 资金·管理：记账中心、报表与利润（成本仅老板可见）、客户管理、数据管理（含同步）

未勾选的功能：侧栏菜单与快捷入口自动隐藏 + 路由守卫拦截 + 动作级拦截。
