## V3.58（SW v87）全局加载 / 切换 / 搜索深度性能优化 + 全系统列表统一 100 条/页

**需求**：用户反馈「页面切换很慢、加载也很慢，需要进行整体性的加载和切换优化，以及整个系统中的面搜索优化」；追加要求「所有涉及列表分页的改为 100 条/页，减少内存加载，速度会更快」。

**先量化、再动手（改造前基准，Chromium 390px，3000 商品/2000 销售单/800 进货单）**：
- 页面首帧渲染：报表 116.6ms、首页 101.1ms、商品档案 66.6ms、销售 49.8ms
- 首屏传输 ~1.99MB，其中 xlsx.full.min.js 861KB + zxing-decode.min.js 407KB = 1.27MB 是**每次启动必载**
- 各页 `render()` CPU 合计 104.5ms

**★ 最大根因（全系统卡顿主因，务必记住）**：`ctx.getProduct()` / `ctx.getPartner()` 是 `Array.find` **线性查找**，而 `profit.topProducts` 会为「每一条售出商品」调用 `ctx.getProduct` 去取名称 → 3000 商品时 **O(n²)，约 450 万次比较**。报表页 106ms、首页 90ms 基本都花在这里。
- 修复：`repo.createContext` 内建**主键索引**（products.id / partners.id）。
- **失效策略（关键设计）**：数组引用变化 ∨ 数组长度变化 ∨ 命中记录 key 的 O(1) 校验；**刻意不依赖 `touch()`** —— 因为批量导入会逐条 touch，一 touch 就失效会退化回 O(n²)。
- 字段原地修改（改库存/成本）**不需要失效**：索引存的是对象引用，读到的恒为最新值。
- `getProductByCode` **保持线性扫描**：条码可被原地修改（长度不变）→ 索引难以及时失效，宁可慢也要正确（调用频次极低，仅扫码/导入各几次）。

**其余四项改动**：
1. **利润聚合去重**：报表页畅销/滞销原为两次 `topProducts`（全表扫两遍）→ 新增 `profit.productAgg` 单次聚合 + `profit.rankProducts` 两次排序取证；`topProducts` 保持旧 API 不变。
2. **首屏 vendor 懒加载**：新增 `js/core/lazy.js`（`<script>` 注入 + 同 key 并发去重 + 失败可重试 + 支持 file://），从 index.html 移除两个大 vendor；Excel 改成 `excel.ensureLoaded()` 后再解析，ZXing 在 `scan.start()` 时预热、解码前按需等待。首屏传输 **~1.99MB → 719KB（−64%）**。
3. **通用区块级局部刷新**（把 V3.56 库存页专属的 `update()` 下沉为框架能力）：`app.render()` 同路由重渲染时先试 `page.update()`，其次 `patchMain()` 逐块比对**只写变化区块**（未变区块零 DOM 操作 → 不闪屏；不调用 scrollTo → 滚动位置天然保持），结构不可调和（数量/标签不符）回落整页替换。为可测把调和逻辑抽成 `reconcileList(oldParent, newParent, depth)` 并接受注入 document。
4. **全系统列表统一 100 条/页**：销售单 300→100、进货单 300→100、商品档案 200→100、库存查询 200→100、预警 PAGE_ALERT 200→100；**盘点 100 与选货区 15 保持**不变。

**改造后实测（同数据集、同环境）**：
| 页面 | 改造前 | 改造后 |
|---|---|---|
| 报表 | 116.6ms | **33.0ms** |
| 首页 | 101.1ms | **35.3ms** |
| 商品档案 | 66.6ms | **49.9ms** |
| 销售 | 49.8ms | **33.2ms** |
| 各页 render() CPU 合计 | 104.5ms | **10.8ms（约 9.7 倍）** |
| 首屏传输 | ~1.99MB | **719KB** |
- 底部导航真实点击切换稳定 ~32ms；翻页/重复渲染滚动位置全程保持（500→500）。
- 无变化重渲染 20.4ms vs 整页重建 31.4ms（约省 35%）。

**重要踩坑**：
- `grep` 工具在本项目对部分文件（page-home.js / page-report.js / profit.js 等）会诡异地返回空结果，改回 **bash `grep`** 即可；看到「应该能搜到却搜不到」时不要误判为代码不存在。
- 本沙箱环境的**下载速率被限制**（33KB 走了 1.2s），浏览器绝对加载秒数失真；**只能对比字节数/请求数等相对指标**，不要拿秒数下结论。python `http.server` 与 Node 静态服务器测出的时间几乎一样，说明瓶颈不在服务器。
- `mount` 只有 `page-account.js` 一个，且不解绑/绑定 DOM 监听器 → 通用局部刷新**保留 DOM 节点是安全的**（这是能做增量写入的前提）。
- 测试里页面 state 是懒创建的：`app.pageStates[name] = null; router.go(name)` 后 `pageStates[name]` **可能仍是 null**，要先 `render()` 或手动 `router.get(name).init()` 再改字段。
- 手机端选货区 `.pick-desktop` 隐藏、`.pick-mobile` 可见 → Playwright 点击要用 `button[data-act="pick-product"]:visible`，否则超时。
