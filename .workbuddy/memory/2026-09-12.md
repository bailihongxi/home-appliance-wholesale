## V3.48（SW v76）根治同路由重渲染跳顶 + 全系统搜索框一键清除

**问题1**：用户反馈销售开单选货区点「加入」、新建进货单「按商品加行」点「加入」也会出现页面跳回顶部，说明不是单一页面 bug。
**根因**：`app.js` 的 `render()` 无条件 `window.scrollTo(0,0)`，任何同路由整页重渲染都会跳顶。
**修复**：`render()` 新增 `lastRoute` 路由变化检测；同路由重渲染前保存 `scrollX/scrollY`，渲染后恢复；仅路由切换时才 `scrollTo(0,0)`。一次性根治所有页面内操作（加入、改数量、切价格类型、搜索等）的跳顶问题。

**问题2**：用户要求搜索框增加一键清除小按钮（类似全局搜索框右侧灰色 X），避免逐个字母删除。
**修复**：全系统搜索输入框统一改为 `type="search"`，启用浏览器原生一键清除按钮（有内容时自动显示）。覆盖：
- `ui.searchBar` 组件（商品档案/销售/进货/记账/客户/供应商/退换货列表）
- 新建进货单选货区内联搜索框
- 退换货换货补货搜索框
- 库存盘点录入搜索框（补充 `data-live="1" data-debounce="1"`，清空后即时刷新）
- `base.css` 显式定义 `input[type=search]` / `::-webkit-search-cancel-button` 样式

**测试**：新增 `tests/render-scroll.test.js`（4 项）；ui-searchbar/ui-purchase/ui-inventory/ui-exchange 各新增断言；ui-mine 版本断言升 V3.48；全量 **680/680** 通过。

## V3.49（SW v77）横向滚动容器（.table-wrap）重渲染保持 scrollLeft

**问题**：手机端销售开单「选货区」左右滑动后点「加入」、当前订单列表横向滑动后改数量/切价格等操作，页面会左右跳动、跳回商品列表最左。用户要求不仅修这一个页面，还要排查其他页面一并修复。
**根因**：与 V3.48 同类——V3.48 仅恢复了 window 级滚动，但 `render()` 整页重渲染时 `app.main.innerHTML` 替换 DOM，内部 `.table-wrap`（`overflow-x:auto` 横向滚动容器，全系统唯一的横向滚动容器）的 `scrollLeft` 被重置为 0。
**修复（app.js render()，系统性）**：
- 同路由重渲染前记录各 `.table-wrap` 的 `scrollLeft`（按 DOM 顺序存入 `savedHScroll`）；
- 渲染后按最小数量 `Math.min(wrapsAfter.length, savedHScroll.length)` 对齐写回，仅同路由时恢复（路由切换不把旧页滚动带到新页）；
- 覆盖销售开单/进货单/商品档案/记账/退换货/库存盘点等所有页面表格的左右滑动保持。
- 暴露 `app._savedHScroll` 便于运行时观测。

**测试**：`tests/render-scroll.test.js` 新增 3 项（查询 `.table-wrap` 并记录/恢复 scrollLeft、暴露 `app._savedHScroll`）；ui-mine 版本断言升 V3.49；全量 **683/683** 通过。
